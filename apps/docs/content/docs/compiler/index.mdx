## Overview

A registry is a directory of source files that belongs to a package. `compile()` scans it for [sidecars](/compiler/sidecar), follows the imports of each installable file, and returns the output in memory.

```ts
import { compile, writeRegistry } from "fuma-cli/compiler";

const out = await compile({
  root: {
    name: "acme-ui",
    dir: "packages/ui/src",
  },
});

await writeRegistry(out, { dir: "public/registry" });
```

## Options

| Option          | Description                                                               |
| --------------- | ------------------------------------------------------------------------- |
| `name`          | Unique name, it prefixes file IDs like `acme-ui:button.tsx`.              |
| `dir`           | The directory to scan for sidecars. File paths are relative to it.        |
| `entries`       | Source files of package exports, see [below](#entries).                   |
| `files`         | Install info of files without a sidecar, see [below](#files).             |
| `external`      | Paths the consumer is expected to own, imports of them are kept as-is.    |
| `dependencies`  | Override the version of dependencies, `null` for the latest.              |
| `subRegistries` | Registries compiled together, files can reference each other across them. |

### `entries`

The compiler needs to know which source file is behind each export of your package, to [keep package imports](/compiler/imports) in installed code.

By default, it reads `exports` in `package.json` and maps `dist` to `dir`:

| `exports`                              | Source file                   |
| -------------------------------------- | ----------------------------- |
| `"./button": "./dist/button.js"`       | `<dir>/button.tsx` (or `.ts`) |
| `".": { "import": "./dist/index.js" }` | `<dir>/index.ts`              |

Specify it when your build doesn't mirror the source directory:

```ts
const registry: Registry = {
  name: "acme-ui",
  dir: "src",
  entries: {
    ".": "index.ts",
    "./button": "components/button.tsx",
  },
};
```

### `files`

The same info as a sidecar, keyed by file path. Useful when it can be generated:

```ts
import { glob } from "tinyglobby";
import type { Registry } from "fuma-cli/compiler";

const files: Registry["files"] = {};
for (const file of await glob("icons/*.tsx", { cwd: "src" })) {
  files[file] = { type: "components", target: `<dir>/${file}` };
}
```

### `external`

Some files only exist for your own app, and the consumer has their own version.

```ts
const registry: Registry = {
  name: "docs",
  dir: ".",
  // `import { source } from "@/lib/source"` is kept as-is
  external: ["lib/source.ts"],
};
```

### `dependencies`

Versions are taken from `package.json` of the registry (`dependencies`, `peerDependencies`, then `devDependencies`).

- Packages of registries in the same compilation use their current version.
- Protocols like `workspace:*` are replaced with the installed version.
- A package only listed as `@types/*` is added as a dev dependency.

```ts
const registry: Registry = {
  name: "acme-ui",
  dir: "src",
  dependencies: {
    // always the latest
    "acme-core": null,
    // inlined by our bundler, but needed by installed files
    "fast-content-type-parse": "^3.0.0",
  },
};
```

## Sub Registries

```ts
const registry: Registry = {
  name: "acme",
  dir: "apps/docs",
  subRegistries: [
    { name: "acme/ui", dir: "packages/ui/src" },
    { name: "acme/charts", dir: "packages/charts/src" },
  ],
};
```

A file in `acme/charts` can import `acme-ui/button` or `../../ui/src/button`, both resolve to the same installable file.

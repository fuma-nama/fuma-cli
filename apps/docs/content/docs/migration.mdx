---
title: Migrate from 0.1
description: Move a 0.1 registry and installer to 0.3.
---

## Registry

<Callout type="warn" title="The output format changed">
  A 0.3 installer cannot read a 0.1 registry, and vice versa. Publish the new registry output and
  your CLI together.
</Callout>

### Split Components into Entries & Rules [step]

`components` only names the entry files, and [`files`](/compiler/files) holds the rules for installing them.

```ts tab="0.1" title="registry.ts"
export const registry: Registry = {
  name: "acme-ui",
  dir,
  components: [
    {
      name: "button",
      title: "Button",
      files: [{ type: "ui", path: "src/button.tsx", target: "<dir>/primitives/button.tsx" }],
    },
  ],
};
```

```ts tab="0.3" title="registry.ts"
export const registry: Registry = {
  name: "acme-ui",
  dir: path.join(dir, "src"),
  components: {
    button: { title: "Button", entry: "button.tsx" },
  },
  files: {
    "button.tsx": { type: "ui", target: "<dir>/primitives/button.tsx" },
  },
};
```

| 0.1                                | 0.3                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `components[].name`, `title`, etc. | Key and info of [`components`](/compiler#components).                                                   |
| `components[].files[]`             | `entry` of the component, and a rule in [`files`](/compiler/files). One glob rule can cover many files. |
| Files imported by a listed file    | Need a matching rule, or to be [exported by your package](/compiler/imports#package-imports).           |
| `dir` as the repository root       | `dir` is the source directory, usually `src`. It must belong to a package.                              |

### Remove Compile Hooks [step]

`compile()` only accepts `root`.

| 0.1                                         | 0.3                                                                                                                               |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `onUnknownFile` returning a file            | Add a rule to [`files`](/compiler/files).                                                                                         |
| `onUnknownFile` / `isExternal` for packages | Automatic: imports of files [exported by your package](/compiler/imports#package-imports) become package imports.                 |
| `isExternal` for files the consumer owns    | [`external`](/compiler#external) of `Registry`.                                                                                   |
| `onParseReference`                          | [`alias`](/compiler/files#alias) to point a file to another, [`preserve`](/compiler/files#preserve) to prefer the package import. |
| `beforeTransform`, `afterTransform`         | Removed. Transform on install with a [plugin](/installer/plugins#transform).                                                      |

<Callout title="This can reveal broken imports of 0.1">
  0.1 trusted the specifier returned by `onParseReference`. 0.3 checks each imported name against
  the exports of your package, so a mapping that was never satisfied now fails the compilation.
</Callout>

If the compilation reports an import that is not a public export, either export it from your package or add a rule matching the file. See [Errors](/compiler/imports#errors).

### Update Registry Options [step]

| 0.1                         | 0.3                                                                                                                                                                                                                                 |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packageJson`               | Removed, the nearest `package.json` of `dir` is used.                                                                                                                                                                               |
| `tsconfigPath`              | Removed, the nearest `tsconfig.json` of each file is used.                                                                                                                                                                          |
| `dependencies`              | Unchanged: override the version of a dependency, `null` for the latest.                                                                                                                                                             |
| `devDependencies`           | Removed. `@types/*` packages are detected from your `package.json`.                                                                                                                                                                 |
| `subComponents`             | Removed. Import the file instead, across [registries](/compiler/imports#cross-registry-imports) too, or list the entries in one [component](/compiler#components) like `all`. References to registries over HTTP are not supported. |
| `meta`, `content` of a file | Removed.                                                                                                                                                                                                                            |

### Route Handlers [step]

Describe the route in a rule, the [macro](/macros) itself is unchanged.

```ts
const files: Registry["files"] = {
  "post-route.ts": { type: "route-handler", route: "api/posts/[id]" },
};
```

### Serve the New Output [step]

`writeRegistry()` has the same signature, but writes a manifest and raw files instead of one JSON per component:

```
registry/
  _registry.json
  files/button.tsx
```

Serve the whole directory.

- The output now contains source files. When it is written into your app (e.g. `public/registry`), exclude it from `tsconfig.json` and your linter.
- Pass `cleanDir: true` once to remove the JSON files of 0.1.

If you validated the output yourself, `fuma-cli/registry/schema` now exports types and `assertManifest()` instead of Zod schemas.

## Installer

### Options [step]

| 0.1                          | 0.3                                                                                 |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| `io.onFileDownloaded(file)`  | `io.onFileWritten(file)`                                                            |
| `io.onWarn`                  | Removed.                                                                            |
| `options.path` in `io`       | `file.output`, the absolute output path.                                            |
| `install(name, subRegistry)` | Unchanged. It is now a shorthand of [`plan()` & `apply()`](/installer#plan--apply). |

`confirmFileOverride` is only asked for the `overwrite` status. Files of [tree-shaken](/compiler/files#treeshake) sources are merged without asking.

### Listing Components [step]

`connector.fetchRegistryInfo()` is replaced by the manifest:

```ts
const manifest = await installer.fetchManifest(); // or fetchManifest("sub-registry")

for (const item of manifest.components) {
  if (item.unlisted) continue;
  console.log(item.name, item.title, item.description);
}
```

A custom `RegistryConnector` now implements `fetchManifest(registry?)` and `fetchFile(file, registry?)`.

### Plugins [step]

Plugins need a `name`, and hooks are called with a [context](/installer/plugins) as `this`.

| 0.1                              | 0.3                                                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `transform(code, context)`       | `transform(code, file)`                                                                                                               |
| `transformImport`                | [`resolveId`](/installer/plugins#resolveid): decide where a file is installed, or mark it `external` to reuse a file of the consumer. |
| `beforeInstall`, `afterDownload` | Removed. Inspect or filter `plan.files` between `plan()` and `apply()`.                                                               |
| `beforeDownload`                 | Removed. Put auth and logging in your connector.                                                                                      |
| (new)                            | [`writeBundle`](/installer/plugins#writebundle), after files are written.                                                             |

## `@fuma-cli/interactive`

The API of `FumadocsComponentInstaller` is unchanged, upgrade it together with `fuma-cli`.
